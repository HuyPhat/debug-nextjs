# Hydra Store: a deliberately broken Next.js app

A small e-commerce site built with **Next.js 16.3 (App Router, Turbopack) + React 19.2 + TypeScript**. It's broken on purpose so you can practise this job requirement:

> _"Solid understanding of rendering modes (CSR, SSR, SSG) and hydration, including how to diagnose and fix a hydration mismatch, and their impact on SEO, Core Web Vitals, caching, and personalization."_

**Nothing is fixed. That's your job.** The bugs fall into four categories:

| | Category | In one line |
|---|----------|-------------|
| **R** | One rendering mode | Every route (even `/about`) is dynamic SSR, rendered on every request |
| **H** | Hydration mismatch | Five different root causes: time, time zone, locale, randomness, browser storage, invalid HTML |
| **C** | Bad Core Web Vitals | LCP ≈ 82 s on slow 4G, CLS ≈ 0.8, INP ≈ 2 s while typing, TTFB up to 1.9 s |
| **K** | No caching | `no-store` on every response (even hashed JS chunks), no data cache, 3× duplicate DB queries |

## Run it

```bash
npm install            # also generates the (intentionally huge) images into public/images
npm run dev:utc        # dev server with TZ=UTC + LANG=en_US, like a production server
# performance numbers must come from a production build:
npm run build && npm start
```

Use Node 20.9+ (tested with Node 22). Then, in Chrome DevTools → **Sensors**, set the locale to `vi-VN` and the time zone to `Asia/Ho_Chi_Minh` so the browser differs from the server.

## Pages

| Route | What it is |
|-------|------------|
| `/` | Hero, flash-sale countdown, featured products |
| `/products` | 600-product catalogue with client-side search, filter and sort |
| `/products/[id]` | Product detail, "people viewing now", add to cart, related products |
| `/blog`, `/blog/[slug]` | Journal (static content) |
| `/about` | Static text |
| `/account` | Set your name and currency (cookies) to personalise the site |
| `/api/products`, `/api/promo`, `/api/track` | Route handlers used by the pages and the analytics snippet |

## Built-in instruments (these are not bugs)

- **Web Vitals HUD** (bottom right): live TTFB / FCP / LCP / CLS / slowest interaction for the current page load. Final values are also logged as `[web-vitals]` in the console.
- **"HTML rendered on the server at …"** at the bottom of each page: if it changes on every reload, that page isn't cached.
- **`[db]` logs** in the server terminal: one line per simulated database query, with its latency.
- `npm run lint` flags some issues; `npm run build` prints the route table (`○ ● ƒ ◐`).

## Project map

```
app/                 routes (layout.tsx is where a lot of the trouble starts)
components/          UI; client components are marked 'use client'
lib/db.ts            fake database with realistic latency + query log
lib/api.ts           server-side helper that calls the app's own API
proxy.ts             Next 16's replacement for middleware.ts
public/vendor/       a "third-party" analytics snippet
scripts/             generates the product and hero images at install time
```

`AGENTS.md` / `CLAUDE.md` are generated by `create-next-app`/`next dev` for AI coding agents. They point at the version-matched docs in `node_modules/next/dist/docs/`, which are worth reading while you fix things.
